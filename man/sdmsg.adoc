== Name

sdmsg - rewrite device or file data in place (SD massage)

== Synopsis

*sdmsg* [_OPTION_]... [_DEVICE/FILE_]

== Description

*sdmsg* rewrites a block device or regular file *in place* so flash media that
sits unused does not lose charge and corrupt data.  Each I/O unit is read and
written back unchanged.  Progress, speed, and ETA go to standard error.
A wxWidgets UI is available with *--gui* when a display is present; with
*--gui*, _DEVICE/FILE_ may be omitted and opened from the File menu.

Two modes are supported:

* *linear* (default) -- treat the target as a raw byte range.  If a partition
  table is present, the table and each partition are rewritten separately.
* *recursive* -- walk an unmounted filesystem (FAT/exFAT, NTFS, ext2/3/4) using
  on-disk structures (not a mounted VFS) and rewrite file data plus essential
  metadata.

A SQLite database records paths, SHA-1 digests, massage/verify counts, and
bad extents.  Partition tables and filesystem metadata use special paths such
as `::mbr`, `::gpt`, `::part-N`, `::boot`, and `::superblock`.

Rewrite always runs against an *unmounted* device and only touches allocated
filesystem data (free space is skipped).  Compressed or encrypted NTFS data is
rewritten as stored on disk (no decryption).  SHA-1 digests are computed
*after* the rewrite, with the filesystem mounted (read-only is enough).  Existing
mounts are always unmounted for the rewrite and restored afterward (including
read/write).  SHA-1 runs when a database is in use: always in headless mode,
and in the GUI only after Database → Open.  The GUI never prompts on the
terminal.  A regular file or loop device is mounted read-only with FUSE.  A
real disk uses udisks, then `sudo`/`pkexec`.  (*fakeroot* cannot grant
`CAP_SYS_ADMIN` and does not help.)  Edit → Dry-run reads the scan and does
not write.

Regular files are opened read/write without truncation.

== Options

*-b, --block-size* _NUM_::
  I/O block size in bytes.  Default: auto-detect (`BLKSSZGET`, file
  `st_blksize`, or 4096).

*-d, --sqlite-db* _FILE_::
  SQLite management database.  Default: `~/.cache/sdmsg/<name>.sqlite`.

*-t, --test*::
  Verify against the database (read + SHA-1); do not rewrite.  Always headless.

*-l, --linear*::
  Raw whole-device/file rewrite (default).

*-r, --recursive*::
  Filesystem walk and rewrite.  Related mounts are unmounted first and restored
  afterward.

*-g, --gui*::
  Open the wxWidgets window (requires `DISPLAY` or Wayland).  _DEVICE/FILE_
  is optional; use File → Open / Device, then Start.

*-v, --verbose*::
  Increase logging.

*-q, --quiet*::
  Decrease logging.

*-h, --help*::
  Show help and exit.

*--version*::
  Show version and exit.

== Exit status

*0*:: Success (I/O errors on individual extents may still be recorded in the DB).
*1*:: Failure.
*2*:: Usage error.

== Notes

Block devices typically require root.  Related mounts are unmounted for the
rewrite and restored afterward.  SHA-1 is computed on mounted file contents
after the rewrite.  Free/unallocated space is not rewritten.  After a run, bad
extents can be exported as a badblocks-style list (GUI offers a save dialog).
One SQLite file can hold several devices (`device`, `volume`, `object`,
`folder`, `file`).  A stored SHA-1 stays valid for 183 days unless Preferences
changes that.
